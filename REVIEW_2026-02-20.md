## 🔴 Critical Issues

### 1. Duplicate Dockerfile at project root

**Files:**
- `/Dockerfile` (root — 50 lines, identical to below)
- `/apps/frontend/Dockerfile` (correct location — 50 lines)

The root `Dockerfile` is a leftover from before the monorepo restructure. The active `infra/docker/compose.yml` correctly references `../../apps/frontend/Dockerfile`. However, the **root `docker-compose.yml`** still references the root Dockerfile (`context: .`), which means running `docker compose up` from the project root builds from the wrong context.

**Risk:** Confusion, accidental builds from wrong context, divergent Dockerfiles over time.

**Fix:** Delete `/Dockerfile`. It is not used by Tilt or the active compose file.

### 2. Stale root `docker-compose.yml`

**File:** `/docker-compose.yml` (61 lines)

This file is **not used by Tilt** (which loads `infra/docker/compose.yml`). It contains:
- Hardcoded `environment:` blocks with `${VAR:-default}` interpolation (the pattern we explicitly removed)
- `ports: "3000:3000"` on frontend (the exposure we removed for security)
- No `env_file` directive
- No cert volume mounts
- References the root Dockerfile

**Risk:** Someone runs `docker compose up` from root and gets an insecure, misconfigured deployment.

**Fix:** Either delete it or replace its contents with a redirect comment pointing to `infra/docker/compose.yml`. Recommended: delete it and add a note to README.

### 3. Duplicate `+page.server` files in contact route

**Files:**
- `/apps/frontend/src/routes/contact/+page.server.ts` — Active, has full email sending logic
- `/apps/frontend/src/routes/contact/+page.server.tsx` — Stale, has TODO comments and no email logic

SvelteKit will load one of these (`.ts` takes precedence over `.tsx` in most configurations), but having both is confusing and the `.tsx` extension is wrong for a SvelteKit server file (TSX is React JSX).

**Fix:** Delete `+page.server.tsx`.

## 🟡 Important Issues

### 4. Missing `.dockerignore`

**Location needed:** `/apps/frontend/.dockerignore`

The frontend Dockerfile copies everything (`COPY . .`) in the builder stage. Without a `.dockerignore`, this includes `node_modules/`, `.svelte-kit/`, `.env` files, and `package-lock.json` changes that bust the Docker cache unnecessarily.

**Impact:** Slower builds, larger build context, potential secret leakage into image layers.

**Fix:** Create `/apps/frontend/.dockerignore`:
```
node_modules
.svelte-kit
.env
.env.*
build
dist
*.log
.git
```

### 5. `lucide-react` in dependencies

**File:** `/apps/frontend/package.json` line 26

```json
"lucide-react": "0.544.0",
```

This is a React icon library in a Svelte project. The correct library (`lucide-svelte`) is also present. `lucide-react` adds ~200KB of unused dependencies.

**Fix:** Remove `lucide-react` from `package.json` and run `npm install`.

### 6. `.env.example` is stale and misleading

**File:** `/.env.example`

This root example file references:
- `TLS=true`, `TLS_CERT`, `TLS_KEY` — not used anywhere (Caddy handles TLS via Caddyfile)
- `EMAIL=your-email@example.com` — should be `ACME_EMAIL`
- `PUBLIC_BASE_URL=https://agency.${DOMAIN}.com` — double `.com` if DOMAIN includes TLD
- Mixes infra and frontend vars in one file

The actual env files are now consolidated: `infra/.env` (all infrastructure) and `apps/.env` (frontend). The root `.env.example` is now an index pointing to these two files.

**Fix:** ~~Either update it to be a "quick reference" pointing to the two actual `.env.example` files.~~ ✅ Done — root `.env.example` is now an index, `infra/.env.example` and `apps/.env.example` created.

### 8. README.md is outdated

**File:** `/README.md`

Several inaccuracies:
- References `Grafana: http://localhost:3001` — port 3001 is no longer exposed
- Says "Caddy will automatically obtain SSL certificates via Let's Encrypt" — actually uses Cloudflare Origin CA
- Deployment section says `docker compose up -d` — should reference `infra/docker/compose.yml` explicitly
- No mention of the `env_file` structure or per-service `.env` files
- References root `.env.example` which is stale

**Fix:** Update README to reflect current architecture.

## 🟢 Nice-to-Have Improvements

### 9. Health endpoint could be richer

**File:** `/apps/frontend/src/routes/health/+server.ts`

Currently returns `{ status, timestamp, service }`. For production readiness, consider adding:
- `version` (from `package.json`)
- `uptime` (process uptime)
- Dependency checks (SMTP reachable, if configured)

This helps Prometheus/Grafana dashboards and incident response.

### 10. Email template file extension

**File:** `/apps/frontend/src/lib/server/email.tsx`

This is a `.tsx` file (React JSX) but contains no JSX — it's pure TypeScript with template literals. The `.tsx` extension is misleading in a Svelte project.

**Fix:** Rename to `email.ts`.

### 11. CSS theme duplication

**File:** `/apps/frontend/src/app.css`

Light theme colors are defined in **two places**: `@media (prefers-color-scheme: light)` (lines 36-61) and `[data-theme="light"]` (lines 63-83). The `data-theme` attribute approach is used by the JS toggle, so the `@media` query is redundant (and they could drift apart).

**Fix:** Remove the `@media (prefers-color-scheme: light)` block and rely solely on `[data-theme]` with JS initialization.

### 12. `compose.dev.yml` uses deprecated `version` key

**File:** `/infra/docker/compose.dev.yml` line 1

```yaml
version: '3.8'
```

Docker Compose V2 ignores this field and prints a warning. The other compose files don't have it.

**Fix:** Remove the `version: '3.8'` line.
